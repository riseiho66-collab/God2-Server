## Implemented Control Plane

tools/strike_lab/ui_gate.py provides explicit transitions, strict readiness
checks, unbounded default waiting semantics, optional operator deadline,
same-run/PID event qualification, health-loss handling, atomic JSON publishing,
and cleanup limited to retained run-owned process objects. A candidate UI
callback alone cannot end the wait. No operation updates protocol truth.
These are unit-tested primitives, not evidence of a responsive live client.
Character-phase and CharacterList knowledge are no longer prerequisites.

## Integrated Lifecycle

- Server lifetime omits --run-for only in rendezvous mode. Target execution
  has no ordinary deadline or event-count limit. Inspection commands retain
  a 30-second failure guard. Other capture modes retain their prior limits.
- Health telemetry runs every two seconds in the debugger output wait loop
  after gate preparation, not through game packets. TCP ESTABLISHED to the
  known loopback endpoint is required. No invented heartbeat is sent.
- Actual prefix TX/RX bytes, login state write, and list evidence are checked
  before readiness. Client ancestry, network breakpoints and both UI candidate
  path breakpoints are verified. No future-state semantics are inferred.
- An OS file lock serializes gate ownership. Cleanup uses retained server and
  debugger process objects; existing debugger cleanup targets its own tree.
- The target is continued after each brief breakpoint inspection. No stop is
  held for operator input. A callback hit alone is not selection success.
- First post-gate network evidence is retained before cleanup. Scatter/gather
  completion remains a blocker, not proof of bytes sent. state.json is not
  promoted automatically from a callback or connection attempt.

Existing prefix startup automation is unchanged. No selection input is
implemented. Selection requires normal external UI interaction.

## Session Hold

Only the long-lived runner passes GOD2_UI_GATE_CONTROL to its server process.
Only recovered server-list mode, session 1, and a loopback peer can consume
this local JSON control file. Hold activation additionally requires the
existing terminal response to have completed. The runner requests hold only
after golden-prefix and observer verification, and waits for server telemetry
acknowledgement before UI_GATE_READY. No GOD2 bytes are generated by control.

The server cancels its application inactivity timer while UiGateHold is active.
Normal sessions retain the 120-second default. Socket EOF/errors and shutdown
still close the session. A ten-second renewable control lease prevents a dead
runner from leaving hold enabled; expiry or release restores normal timing.
last_real_protocol_activity changes only on real socket reads/writes, not lease
renewal. The .status sidecar reports policy, hold time, activity and liveness.
Post-gate capture and cleanup release hold. ui_gate.json requires and exposes
server_session_hold_active before reporting readiness.

## Cancellation Control

Create cancel.request inside this run's artifacts/runs/<run-id> directory,
or select --ui-gate-max-wait at launch. Cancellation interrupts only the
validated debug target and follows run-owned cleanup. Global ui_gate.json
and ui_gate_result.json are mirrored into the run directory.
