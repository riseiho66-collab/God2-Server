movement_rules

中文名稱：一般移動設定
用途：CUSTOM-0150 明確選用的一般移動備援規則設定，不是原廠移動公式、角色存檔、封包、地圖或逆向證據表。
分類：遊戲規則設定；一列代表一組明確選用的設定，台服／陸服協定差異不自動產生分表。
來源：src/db/SqliteOrdinaryMovementPolicyRepository.cpp 的 schema() 與 load()。
本輪只有 C++／DDL 來源，未安裝資料表、未填資料、未啟用政策、未執行 SQL。

欄位說明（實體表名及欄位名一律英文）：
profile_key | 設定代號 | 文字主鍵；1～48 個 ASCII 字元，首字為小寫 a～z，其餘限小寫字母、數字、底線。大小寫精確比較；不接受空白、中文、隱藏字元或自動去除尾端空白。
config_version | 整批設定版本 | 整數 1～9223372036854775807；單位為版本序號，不是原廠封包或角色等級。全表每列必須相同。
step_interval_us | 每步補充間隔 | 整數 1～60000000，單位微秒（1000000 微秒＝1 秒）；每完整間隔補充一步額度，額度不超過 burst_steps。
burst_steps | 額度上限 | 整數 1～39，單位步；限制可累積的移動額度。39 只用於本設定與已核對的保留槽環形佇列條件，不能據此聲稱原廠伺服端限速相同。
initial_credit_steps | 初始移動額度 | 整數 1～burst_steps，單位步；新實際場景權限建立時的初始額度，不能用熱載入替舊權限重設進度。
first_sequence | 第一個預期索引 | 整數 0～39；本備援政策明確選用的起始索引。不是原廠伺服端索引回覆或重設規則的證明。
block_players | 阻擋其他人物佔用格 | 整數 0 或 1；1 表示啟用本備援規則的目的格人物阻擋，0 表示不採用該項阻擋。實際角色／場景資料與代次仍由權威核心提供。
forbid_corner_cut | 禁止斜走穿角 | 整數 0 或 1；1 表示斜走要求相關側格可通行，0 表示不採用該項限制。未提供完整原生場景資料不能以此偽造可通行地圖。
allow_zero | 允許原地步驟 | 整數 0 或 1；1 表示允許座標不變的請求，仍必須通過本政策其他序號、額度、場景、身分條件。
design_id | 規則來源識別 | 文字固定 CUSTOM-0150；表示自訂備援設計，不能改成原廠標記。

型別與資料完整性：
SQLite 的整數欄均有 typeof(...)=integer、NOT NULL 與範圍 CHECK；文字欄有 typeof(...)=text、NOT NULL 及文字規則。SQL 整數親和性可能將可精確表示的輸入轉成整數，load() 以實際儲存型別為準，再檢查數值域後才轉成 C++ 型別；不允許將文字、浮點數或 BLOB 當讀取捷徑。
profile_key 唯一；全部資料按 ASCII 代號排序。設定不得空表，呼叫者必須明確指定整批上限 1～1024；超量、重複、混合版本、非法型別或欄位值會整批拒絕，不發布部分資料。
沒有遊戲數值 DEFAULT，沒有預設資料列，不從其他設定代號或區服補值。

修改與重載：
管理者應在同一個資料庫交易中修改所需參數，並把全表所有列的 config_version 一併改成新的較大版本，再提交。刪除／新增設定代號也屬同一整批版本變動。
一般移動權限以明確選定的 profile_key 取得完整型別資料；只有完整讀取、驗證後的整批設定才可發布。同版本內容被改動或版本倒退會由實際設定快取拒絕；單表 CHECK 無法強制跨列版本一致，load() 另作整批檢查。
每次實際 authorize 會取得精確的新設定觀察，將候選步驟與整份有效政策一起凍結；只有唯一共用位置 CAS 成功後才採用該政策。熱載入保留目前序號、位置、發布代次，以及按舊政策已累積的完整／不足一步額度，不以版本變動重新給初始額度；first_sequence 與 initial_credit_steps 只在新的實際權限建立時使用。已發票據需精確政策觀察與生命週期檢查，不能在 CAS 前後偷換資料或以同版本更新內容。實際場景、原生回覆完成憑證與完整遊戲路徑仍需各自接妥。
load() 只讀 main 的實體表，拒絕同名 TEMP 遮蔽與借用外來交易；使用自己的一次讀交易，查核同連線寫入量、執行緒、重入與實際倉庫生命週期。此範圍不宣稱已解決任意外部 SQLite hook／交易 ABA。

mysql80_schema() 回傳與上述單表 DDL 相同的完整約束文字；mysql80_snapshot(max_profiles) 先透過實際 load() 完成一次整批同版本讀取，擁有全部已驗證設定後，才組成完整 DDL 與明確欄位 INSERT 的一個 C++ 字串。數值使用精確十進位，設定代號只允許已核對的 ASCII 字元，沒有機器碼／BLOB；不寫檔、不印資料、不對資料庫執行輸出 SQL。
輸出只能匯入尚無該表的目標，不能跳過既有表、丟掉 CHECK、DROP／REPLACE 或 IGNORE。MySQL DDL 可能隱含提交，所以本輸出不宣稱整批 schema＋資料匯入具交易原子性；檔案原子發布、整個資料庫一致匯出與正式匯入仍待實作／驗收。
本單表不代表 MySQL 後端、全部 SQLite 無損匯出、資料遷移或正式啟用已完成。
