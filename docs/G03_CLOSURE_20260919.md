# G03 Closure Experiments

## Decision

G03 remains **NEED_MORE_EVIDENCE**. G04/G04.5/G05 remain deferred.
Existing G02 certificate `00eca96509354ee53ea0bb1b4a7890a0d5461385df65506a94e856977022d3a2`
was audited successfully, not reissued. No existing evidence or issuer was changed.

The third initialization routine's caller continuation at **0x54A46E** was reached
in four fresh runs, including two explicitly resumed from **0x5479BD**. The ledger
classifies these as RETURNS at the caller-continuation level. Because there is a
trace gap before that stop, the exact final RET instruction or tail-transfer is
not established. Do not equate this classification with full callee coverage.

## Blocking Coverage Finding

All four logs contain an x86 far jump at 0x77547000 into the WoW64 transition,
followed by a discontinuity before the final caller continuation. The candidate-
start runs omit several expected startup call sites entirely. Matching row counts
or matching endpoints therefore cannot prove matching complete semantic paths.

Every recorded PC was scanned against the full .aspack range
[0x702000,0x706000). There were no hits within the defined trace windows. This is
**no observed return in recorded PCs**, not full-range execution coverage: mode-
transition gaps remain. No region-wide breakpoint or complete branch trace was
installed. The instruction budget of 20,000 bounded output/time only; the expected
return breakpoint ended each run before exhaustion. It is not a success threshold.

The proposed stable window still requires complete critical call/return coverage
from candidate through third-routine completion, repeatable branch decisions,
whole-window packer-range monitoring and no spontaneous termination. These
experiments close the endpoint question but do not meet all coverage requirements.

## Ledgers And Cross-Checks

Authoritative derived outputs: `artifacts/reports/g03-closure-20260919-v2/`:

- startup-call-ledger.json: observed calls, direct targets where decoded, next
  observed PC, return-address/ESP matches and result registers. Unknown indirect
  targets remain null, not invented. Missing callee entry is not marked seen.
- startup-branch-ledger.json: native sites, conditions, next observed destinations
  and register snapshots; a branch ledger is not proof against unobserved paths.
- runtime-static-correlation-v2.json: all recorded register-backed instructions,
  native/CDB decoding, Capstone decoding, boundaries and client mapped-byte checks.
  All client rows match and all recorded boundaries decode. External rows lack
  a module memory image and are explicitly native-only for byte comparison.
- protection-timeline.json: actual !vprot snapshots at packed/transfer/candidate
  and caller completion where emitted. After-A/after-B snapshots were not captured
  by these experiments; this remains incomplete, not filled from another run.
- closure-review.json: outcomes, coverage gaps, packer scans and image differences.

Initial generated directory `g03-closure-20260919/` is SUPERSEDED, not deleted.
Its analyzer incorrectly treated segment-qualified memory operands and repeated
string steps as coverage gaps. V2 restricts mode-transfer findings to appropriate
instruction types and allows observed REP repetitions. Native logs were unchanged.

The before-end .text comparison found zero changed byte positions in every run.
Whole-image differences were 71/71/67/71 bytes respectively. This is endpoint
comparison only: transient writes restored before the end dump are not excluded.
No complete new-decompression or self-modification detector was established.

## Separate Protection Claims

Current PAGE_READWRITE remains recorded for the client. The earlier deep capture's
three successful DEP flags=0 samples apply to that earlier PID only. These new
runs did not query DEP, so that finding is not silently copied into them.
CLAIM_PROCESS_DEP_DISABLED_AT_SAMPLED_POINTS and CLAIM_PE_SECTION_EXECUTABLE remain
separate; executable PE flags were not changed or certified.

## Next Experiment

Address the debugger's WoW64 trace discontinuity with a validated mode-aware
trace/capture method, then repeat the same window. Do not add more instruction
count and assume that fixes lost coverage. Direct stop/return evidence can guide
the next experiment, but no G03 certificate can be issued from this gap-containing
trace alone. New runtime sessions must receive their own formal identity and
prerequisite review before certification; these diagnostics borrow no G02 receipt.

Parser regression tests passed (2 focused tests). No C++ changes were made and
the full suite was not rerun this turn; the prior 70-test baseline is historical.
All client/debugger processes were checked exited after capture.
