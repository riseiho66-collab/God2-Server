# 目前原生 C2S 單零位元組包裝函式 census

同一 verified mapped image
`149c1b4510a2dee85eb988d3f6c05785a69cbf50bb8fb751af7d9814a5a6e763`
的 PE `.text` 中，直接 E8 呼叫 `157D0` 或 `961A0` 共31處。
每個呼叫點的原始 E8、對齊 `push`、前20 bytes，包裝函式原始
指令、`96274` 跳表與 `9628C` selector bytes 都保存於
`artifacts/integration/packet-connections-20261006/c2s-wrapper-census-v1.json`。
這是有界靜態來源證據；沒有執行原生客戶端、測試、build或部署。

`157D0` 將 caller opcode 與**一個常數零位元組**交給 `132E0`
佇列，故其成功入列的 C2S logical 佈局是 `opcode,00`。
`961A0` 先以第一個正式參數查 `9628C`；在 `1F..6D` 區間只有
五個 opcode 不是 default：

| C2S opcode | selector | 包裝分支／限制 |
|---|---:|---|
| `1F` | 0 | 第二參數非零直接入列；零時先看 UI 狀態 bit20 |
| `23` | 1 | 入列 `23 00` |
| `31` | 2 | 入列 `31 00` |
| `68` | 3 | 依客戶端 `+8AA4C/+F4` 的低兩位，可能改走本地訊息而不入列 |
| `6D` | 4 | 入列 `6D 00` |

另一個直接 `157D0` caller `68A7C` 推入 `22`，形成第六個
包裝器 opcode 候選 `22 00`。`1F/23` 的世界初始化路徑、
`6D` 的控制路徑先前已有局部來源；`22/31/68` 尚無可核定的
服務端效果、回覆與階段時序。`68` 不能因 caller 出現就視作
每次都會送出。部分 caller 的第二參數來自暫存器，條件仍需追蹤。

先前直接呼叫 `132E0` 的靜態參數候選 opcode 有145個；這六個
與該集合**沒有重疊**，故目前「直接＋此兩個已知包裝函式」
的不同參數候選聯集是151。這不是151種完整封包，也不是全遊戲
producer 分母：間接呼叫、其他包裝器、變體與前置狀態仍未窮盡。
本輪沒有把未知 `22/31/68` 加為成功 handler 或獨立業務回覆。

後續 `current-c2s-wrapper-frontier-20261006.md` 進一步指出
`22` 所在的第二分流函式 `68A30` 尚無直接 E8 caller 可達性證據；
同一分流中的 `35` 另有只寫入 body offset8..11=`FFFFFFFF`
的 raw 變體候選，不能混作已接的戰鬥 action。
