## Character deletion dependencies

The existing owned erase implementation in SqliteRecoveredCharacterRepository
collects character_id tables along the recovered_characters foreign-key graph,
clears children and deletes the owned character in one deferred-FK transaction.
Both PET custody and selection already join that graph. No new deletion handler
or generic success packet was added. The existing authenticated19 request,
slot/name/world-state checks, native02 result and02/04 logout handshake remain.
The discard journal intentionally has no owner FK and survives as removal
history; feature ledgers have no character_id and remain unchanged. This is
source dependency composition, not executed deletion acceptance.

Open work includes original bind/activity/transfer rules, bank custody,
acquisition/rewards, ground drop/pickup, food, riding, exploration authority,
self/observer appearance and all remaining whole-game routes. Comprehensive
testing and repair remain later phases; no whole-game percentage is claimed.
