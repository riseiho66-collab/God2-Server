# CN login composition bound to actual shared world preparation

PHASE1 source integration only: no builds/tests/native/server/Lua/resource execution, gameplay DB access or deployment. Levels unchanged. Pinned CN contracts retained from the existing selection/preparation receipt, not newly invented.

Previously SharedLoginSources::World accepted Selected and presence independently. Comparing the deletion guard to the separately supplied presence did not establish that the arbitrary Selected callback used that registry. The world continuation now requires an actual SharedWorldPreparation pointer. Before attaching the world selection owner, compose_native_login compares its retained character repository and map catalog to the listener Context, obtains its real presence_registry(), and checks complete deletion sources against that exact registry. It obtains Selected only through preparation.selected(), which retains the same controller.

The new owns_sources() accessor checks exact object identity on the serial game owner; it neither queries SQLite nor grants native permission. RecoveredCharacterRepository/NativeMapCatalog remain the actual host-owned sources and must outlive drain. Absence or foreign sources fail before native1F selection attachment; no success or fallback controller is invented. The world supplier no longer accepts independent .selected or .presence fields and must return .preparation. No concrete enabled provider in the current source tree used those removed fields; future configured providers must use this typed API.

SharedServerPlan::Context already exposes a const NativeMapCatalog. The actual preparation and initial-scene APIs now borrow const NativeMapCatalog& consistently, so a controller can be constructed from that exact Context without casting away constness or duplicating the catalog. Their only catalog operations remain existing lookup() calls; scene qualification, loaders, movement adoption, transfer handling and save mutations are unchanged.

The existing preparation still requires common presence/visibility, pinned assets, a real actor Reservation, full native02/2A, generation-qualified saved position, initial scene or actual transfer qualifier, and gameplay/movement authorities. This source wiring does not implement those missing suppliers, bootstrap issuers or production placement/rules. It does not prove TW lifecycle uses that registry; actual common/legacy host wiring remains necessary. Native deletion permission, guild/replay/receipts and1E remain open.

Application, Session, actual credential auth, listener, selection owner and removal occupancy implementation remain byte-identical. The account success/catalog lambda body remains byte-identical inside the changed composition file. This is an existing conditional source seam strengthened once, not a new owner chain/opcode/phase count; prior preparation owner is not counted twice.
