## Explicit CUSTOM-0098 policy and authority boundary

The selected server policy extends the existing opt-in transient directory.
C90 resolves only a row issued to this exact owned query, its full Session and
common owner mapping, current listing, current scene and actual shared party
state. Details are not a free lookup by public WORD. The display policy selects
the target first, then actual group participants in stable full Session order,
up to the native four-row capacity. A solo target is a real one-row detail.
This is custom display selection, not a recovered official roster rule; a
five-person party cannot display all five members in this four-slot layout.

Every displayed role must have qualified name/level/profession and an actual
owned Photo4 baseline. A new private detail observation binds the complete
read set to the query; changing query/page/close, target ownership or relevant
party state must not leave reusable join rights. Native status/header choices
are explicit custom presentation policy, not inferred server authorization.
Each new C90 retires the same Session's previous detail before attempting the
new lookup, including when the new selection is unavailable. A failed selection
cannot leave the previous target authorized after the native detail cache clears.
Other participants reuse actual previously captured directory or companion
restoration private entry observations; missing observations remain unavailable.

C91 resolves the owned issued detail again and reobserves the actual source,
target and party state before entering the existing NativeParty Join operation.
It creates a pending offer and sends the existing S54 preview to the target.
The existing C58 answer path remains responsible for accepting and publishing
membership and roster/vitals/position replies. No directory click immediately
joins a party, and no new success ACK or replacement consent opcode is invented.

The existing NativeParty adapter still represents character identity as a
bounded common WORD. This increment can bridge only when the full common ID
fits that adapter and exactly equals the actual emitted native actor handle.
It does not truncate a full common ID or allocate unrelated directory handles.
Other mappings remain open. Existing preview HUD projection and resource gates
remain distinct from AB's explicitly selected Photo4 entry baseline; equality
between those two presentation suppliers is not an authority condition.

Prepared response/projection bytes precede publication. Complete actual owner,
entry, role, movement and party observations are requalified before committing
the directory and pending-offer state. NativeParty's full readonly state
comparison covers members, groups, membership and pending offers including
expiry; it does not change the existing consent rules. Queue submission is not
remote receipt or acceptance.
Across detail and join requests, only relevant owner/party identity and
membership are compared. Ordinary movement within the same scene and unrelated
players' pending offers do not invalidate the selected party.
