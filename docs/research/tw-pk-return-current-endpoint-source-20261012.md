final snapshot, while positions were observed separately via Presence and the
complete scene supplier. After Publication's actual terminal SQL reads, the
stored-only cut re-read no full common root/pose. With zero directed actors it

from source-edge text receipts. A configured full scene still needed a concrete
shared-storage current-root/pose source, independently of its native resources.

`impl_->recovered_characters` into the existing private
`OwnedTaiwanPkReturnRoleTextSource`. Constructor and operation identity checks
require its exact connection and the exact repository owned by Presence.
No public repository supplier or caller-created root receipt is accepted.

The private return plan seeds **both returning participants** in its endpoint
map before the actor loops. Every directed source and recipient then shares the
same map, deduplicated by session with exact lease/position/Session/battle tuple
equality. Canonical endpoint requests are allocated before source observers.
Thus an empty scene still has two endpoint requests; text rows continue to use
directed-actor cardinality, independently of endpoint cardinality.

`observe_endpoints` reads each complete actual common root and full saved pose:

- Concrete `list_for_account` proves account existence and validates the owned
  root, including profile/name consistency, slot, creation time, codepage and
  streamer style. Account credentials are not copied or changed.
- Concrete `load_position` proves ownership and returns area/scene/x/y/revision.
  It must equal the **current plan pose**, never original `Lease.position`.
- Private endpoint receipts retain owner identity, exact lease, all root fields
  and complete pose. Complete root comparison includes id/account/slot/profile/
  created_at/name_codepage/streamer_privilege. Roots have no independent native
  revision: this is exact retained-value qualification, not arbitrary external
  SQL ABA detection.
- Presence observers run outside SQL scopes. A second whole endpoint snapshot
  follows them; only pure retained Presence checks follow that snapshot.

Prepare stores these private receipts once. Retained observations do not refresh
them to hide a change. `stored_current(text_rows, endpoint_rows)` compares every
retained text/guild/epoch/root/pose in **one actual read snapshot**. Both the full
Visibility read and Publication's existing stored-only cut consume it; the latter
remains after actual saved-terminal-resource and both context SQL reads, followed
only by pure registry/Session/pair checks.

Actual main-table and TEMP-shadow checks now include accounts and
recovered_positions alongside the four existing text/guild/root tables. Missing
root/position, changed complete tuple/revision, wrong owner, namespace shadow,
recursive entry, operation DML, connection or transaction mismatch fail the plan.
The persistent Visibility and source guards remain. `owns_database`/`unchanged`
allow the Presence thread guard's exception to reach the existing fail-closed
catch, rather than declaring that guard noexcept.
