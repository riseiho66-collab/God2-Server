# TW actor resource source — 2026-10-15, round 413

The ordinary actor material path now has a concrete C++ asset source. It receives
exactly the backend-issued shared PopulationInput, row and joint equipment token,
derives the four ordinary Hero lookups through the existing private argument
source, performs the native-qualified file selection, decodes the selected ROM
in future product execution, and binds each explicitly configured full action.
The implementation is source only; none of those product operations was run.

The new host assembly method creates the argument and asset owners on the actual
Application game Context using the same private bank nodes already installed by
the complete scene-entry offer/qualifier pair. It supplies their actual observe

retained status supplier. It does not infer ordinary status from a missing EA
packet, zero transform or zero streamer flag. Main remains opted out.

## Evidence, scope and origin

Original 149c argument and selector/header joins are retained from round 412.
This round adds no native instruction/data byte novelty, opcode, formula or
receive-format classification. The corrected original DA fields remain transform
3/4, raw scalars 5/6 and eight component bytes 7..14. The explicit fresh full
actor projection and ordinary-only return composition remain CUSTOM-0133.

All four NativeRomContext values, four full action operands, encoded/plain byte
bounds, resource scope and optional CUSTOM selectors are supplied explicitly.
Configured action choice is CUSTOM host configuration; proving that a requested
action exists is not proving the native client's current chosen action.

CurrentServerImmutableAssetGeneration means this strongly owned server source's
immutable asset/configuration generation. It never means the physical files have
not changed or a native client's cache/window/ROMFILE manager remains current.
WholePhysicalSelection reselects each requested component and compares the whole
request context, candidate and actual paths, full rejected candidate original,
probe, fallback branch and opened selected bytes. Those sequential observations
do not establish atomic filesystem state. Empty Hero filenames are selected
empty rows; missing requested files/actions are refused. The independent selected
DrvDoll tail must actually have an empty filename in this ordinary V1 subset;
a nonempty tail is still unsupported. A zero selector never skips all four Hero
components or assumes Drv0/DrvDoll0 is absent.

## Ownership and validity

The weak private cache key is the exact shared input node, row and joint equipment
observation. Repeated recipient edges share the same private data and epoch.
Expired cache entries retain neither old inputs nor ROMs. The source has its own
private identity and increasing epochs; a later node cannot reuse a prior token.
The fixed cache allocation bound is a server bound, not a recovered native limit.

ResourceInput retains private data; its private callable target retains the same
source and data. Data contains inputs, arguments and ROMs only and does not own a
Profile, Scene or its own ResourceInput closure. Current first finds an installed
private cache node and verifies the private callable target, exact argument token,
all selectors/Origin, bank nodes, component lookup fields and ROM nodes. It never
casts an arbitrary shared<const void> into a private Data object.

Game-thread and reentry retirement checks precede observer operations. All data,
cache installation and returned closures are allocated before the final qualified
saved/equipment read cut. Subsequent checks are pure private ownership/material
fences. Resource validity is independent of receiver Prepare/Retained/Consumed;
Profile and Scene retain the actual private endpoint phase fences. No old accepted
NormalINIT is invoked to stand in for the consumed return successor.

Scene material callbacks now take shared_ptr<const PopulationInput> by value,
passing the actual private node rather than losing its lifetime through a
reference or constructing an alias/copy. The host helper retains resource and
status dependencies strongly and directly delegates to the actual SceneOwner
return supplier, without a dummy or earlier external ReturnScene callback.
