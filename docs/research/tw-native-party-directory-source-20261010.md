Phase1 source integration. No build, compiler, test, runtime, client/native,

## Native source and explicit policy

Mapped149c source qualifies C8E/C8F logical25 (complete24-byte query), C8D
logical2 and C92 logical2. A7 is logical5+44*n, up to6 rows. Each row retains
IDWORD, flags, level, description22, profession and name17. Native A7/AB readers
permit bounded unread remainders; no stricter native divisibility is invented.
Nine exact peer5fcf intervals match149c, not the complete images. The native
archive retains15 bounded code spans/1,967 bytes/630 instruction sites.

The raw first two query bytes remain opaque selectors. The current native query
is not necessarily zero: the retained reset prefix sets both selectors to FF.
Post-NUL bytes are preserved. C90's upperWORD comes from the full caller argument;
C91's upperWORD comes from saved receiver ECX. Neither is a proven zero or nonce.
The unmodified peer receipt and these independently recovered corrections remain
separate evidence.

CUSTOM-0097 labels the server directory policy: transient same-scene listings,
owned publish/update/query/close/withdraw/page behavior and canonical0 A7 header
and row flags. These are not recovered official server rules. Query selectors do
not grant permission or acquire guessed filter meanings. Actual common saved
name/role fields supply name, level and profession. No name conversion or common
ID truncation supplies native identity.

Actual emitted2A actor handles and full common owner identities remain separate.
The exact Session's private normal-entry transcript supplies the handle and its
current ownership. A directory row cannot allocate an unrelated player ID merely
because it fits a WORD. Any same-handle ambiguity must reject the projection.

## Source integration scope

The four actual source branches are C8E query, C8F publish/update, C8D query
close/owned withdrawal and C92 previous/next page. Their directory is common
game-owned transient state, distinct from actual party membership. Existing
NativeParty invite, consent, kick and leave remain in their current core.
Publication prepares the response and requalifies exact current sources before
publishing its state. Replies retain native framing and original input order.
The first three reply-producing operations (query, publish/update and page)
return A7. C8D1 retires the query and its issued mapping; C8D2 also withdraws
the owned listing. Both are one-way lifecycle operations with no invented ACK,
A8 or AC. Other viewers refresh by querying; no live watcher push is claimed.

Full64-bit common IDs remain distinct from the actual emitted native handle.
The source reads the private written/current initialization, complete common
profile/slot/codepage/creation/streamer tuple, saved role/revision/design and
movement position/revision. It adds no old party HP or common-ID limit. An actor
handle collision, including with a viewer who has no listing, rejects projection.
Listings, queries and each query's retained issued map are bounded by the actual
max_sessions. An exhausted issued map requires closing/reopening that query;
it never silently rebinds an already-issued ID to another owner.

The custom order is stable full Session ID order, six rows per page, with page
bounds clamped to the current eligible list. The complete24-byte query is owned.
Published descriptions and every outgoing A7 description receive exact CP950
roundtrip qualification before NUL; the original trailing bytes remain intact.
A successful actual world_ready hook retires this exact Session's old listing,
query and issued mappings, after the existing ready/blacklist hooks succeed.
Disconnect also retires this Session state. The directory is allocated only
when its feature is selected.

The feature uses world.owned_party_directory.enabled and defaults off until the later activation
phase. This source document is not evidence of runtime acceptance.

C90/C91, complete AB member details and actual joining through this menu remain
unfinished. AB appearance4 cannot be borrowed from the old HUD4 or6bf custom
appearance. Cross-session live watcher propagation, original filter semantics,
full native window lifecycle and any missing post-battle identity renewal remain
open. No queued request is counted as server acknowledgement or membership.
