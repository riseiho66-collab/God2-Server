and exact S2A written, every round250 batch handle current/exactly written, and

not reject the old world handler. NoRecords remains distinct from a batch write.

The handler captures its creation thread and rejects/reentry-poisons a nested
prefix read. It owns copies of Restoration and expected model before SQL
observers. It reads each unique saved S34 definition from the real catalog,
recomputes the complete110-byte row's SHA-256 using Windows BCrypt, and compares

and the complete saved deity readset. `_current` rebuilds from the actual saved
material and compares full modeled rows, count, selector, all referenced full
catalog records, and the complete original batches/boundaries.

The new `NativeSkillCatalog::lookup_main` explicitly selects
main.native_skill_catalog and main.native_data_sources. It shares the existing
row/metadata parser with `lookup`; the original lookup's resolution and behavior
remain unchanged. The new source cannot accidentally read a TEMP table instead
of those main tables. No schema/write/migration or new link dependency is added;
the existing Windows bcrypt link supplies the row digest path. On non-Windows,
referenced-row digest unavailability rejects a nonempty learned prefix; a reset
or pet-only model still obtains no inferred catalog provenance.

These are sequential saved/catalog observations, not one atomic cross-source
snapshot, a future CAS or lasting freshness. Only referenced definitions are
read and hashed, not all448 rows, complete source file, native loaded memory or
loader success. An empty learned set obtains no catalog provenance by default.
Existing owned material retains its original CUSTOM-0039/display qualification;
none is promoted to native learned/cast rights.
