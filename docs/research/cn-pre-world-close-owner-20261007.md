## Source connection added

SharedLoginSources::World now carries terminal_close from the existing actual
world supplier. compose_native_login passes it to SharedWorldSelection::attach.
The selection receiver consumes the qualified exact two-byte C2S02 forms only
before world entry and after its real1F offer queue callback. Selected world
ingress retains its existing dispatch; the opcode is not intercepted in-world.
Other02 controls and multi-record aggregates remain outside this bounded branch.

The receiver takes a terminal-only stage before invoking the source. It supplies
the verified common account, lifetime-unique world session and parsed form to
the real provider. SharedPreWorldCloseReply preserves all three actual native03
bytes and a required current-operation predicate bound to that exact scope.
Its factory validates structure, never generates bytes or grants permission.
Missing providers/records, exceptions and stale operation/scope fail the branch;
there is no fallback response. The source callback is synchronous on the serial
game owner and must not retain a borrowed scope reference.

Current checks combine the exact committed admission ticket with the selection
owner's exclusive terminal stage and the supplied actual operation predicate.
The provider must independently check the real phase, save/operation/replay state,
not just echo the supplied account/control or return a constant true predicate.
It must retain valid operation ownership through reply queue acceptance; the
pending terminal stage is not a durable operation receipt or storage transaction.

Complete03 reaches SharedCredentialConnection::close_after_native_world_reply.
That existing code repeats its current-owner check before queueing and after
queue acceptance, then invokes CnTransportSession::drain_and_close. Terminal
input remains suspended and cannot begin a second close, selection or deletion
identity resolution. Original credential aliases are cleared before queueing.
The same world transport performs its existing generation-qualified cleanup;
the separate account connection is not closed by this source.

Actual committed deletion may already invalidate its old07 offer. This terminal
path therefore checks world_admission_current rather than qualify_offer or
character_offered. It neither rewrites07 nor invents a shorter common-ID list.
The exact world ticket remains required even when its historical offer is stale.

Drain completion intentionally reports the existing local-write boolean without
checking closing/ticket afterward: closing and cleanup are expected by then.
It is not client receipt, native acceptance or completed gameplay. The ingress
completion is single-use across its asynchronous callback and exception path.
