## Original-batch capture

SharedGuildApplication53Draft now separates capture(full original records)
from execute(captured, original index). The opaque Prepared owns copied records,
frozen opcode/help/admission-choice classification, old publication/pending
evidence, all mutation plans, original mixed-domain policy and whole-frame
help safety. There is no recapture after an unrelated prefix. No public
constructor, copied Prepared, caller-supplied membership, slot identity or raw
metadata can manufacture its private issuer identity.

Execution checks exact adapter/token/Common/session and current admission issuer
identity, consumes only the next selected original index before callbacks, and
rejects replay, skipped indices and same-Prepared reentry. Retirement targets only captured old
neighbor/pending evidence and latches before cleanup. Admission replacement gets
a new private identity even when the same pointer is installed again. Ordinary
policy refusal stays distinct from an invalid execution attempt; committed
work is never described as rolled back on a later failure.

Results distinguish None, UiAttempted and MutationCommitted; UI attempts provide
no queue/Written/publication/client-ACK evidence, and None promises no rollback.
Callback/audit exceptions retire the batch, attempt both exact cleanups and
rethrow the original exception. A context callback is refenced before help dispatch.
Retirement prevents later adapter records; it cannot cancel Common/admission side
callbacks already entered. A nested fresh capture is not an adapter-wide
continuation fence. Those deeper source gates remain open before native use.

Legacy handle/handle_reply now delegate to this same capture and executor while
preserving prefix composition and LegacyWorldReply private C67 ranges. Empty
input/null-prefix/null-Common still refuses. Legacy prefix callbacks receive the
actual incoming records.subspan, not the owned copy: Session C28 checks the actual
request address, and movement custody retains original record/run provenance.
Prepared copies serve only frozen action plans; future native Current/children
must also retain their actual original spans. Full-original-frame help safety,
mixed-domain refusal and lone-announcement restoration are retained. Choice
recognition is deliberately frozen before admission.capture can revoke a mixed
dialogue, so it cannot be reclassified or acquire a later-created grant.

The captured session is a full64 scalar, not an actual Session/presence lease.
A future native holder must independently retain/check exact Session pointer,
world identity, phase/battle/readiness and original native full-batch Current.
This adapter API alone does not provide those capabilities. Captures must retire
before their actual GAME/DB host lifetime ends; shared Common ownership does not
own its repository references.

## Actual sender and acceptance chain

Application Common53 send validates its current local owner, binds the delivery
identity and calls Session::send_world_records_with_acceptance. Session first
observes the AcceptedWorldRecords component, reserves logical.size()+3 bytes
and one producer slot, then posts to NET. NET checks the full delivery tuple and
battle generation, calls the existing RecoveredWorldFrame::encode path, appends
the Write to FIFO, and immediately reports acceptance(true), before async write
completion. Application posts that bool to GAME behind its lifetime fence.

This is queue acceptance, not Written or native client ACK. Session callback
component Written is a separate exact-frame async_write completion path.
Observing a generic component does not hold or reorder it and does not retain
the original acceptance callback. The existing sender encoding path is observed
source, not proof that its lab profile qualifies the actual native peer.

Menu acceptance publishes the entry lease. Prompt acceptance publishes the
conversation. Common sync acceptance rechecks the exact lifecycle/cache and
publishes roster/notice/pending capabilities. Bootstrap sends one of11 chunks
at a time; each accepted callback schedules the next, then the completed
baseline permits Common sync. Wallet and native name outputs also need their
original position and transport custody, even when they carry no grant ACK.

LegacyWorldReply/Session private C67 deferral cannot be repurposed: its origin
is an actual C67 claim and complete32-byte S31 frame with matching key. It stores
no generic acceptance callback. Tagging guild7A/8D/91/98 bytes would fabricate
selection provenance. This round changes no Session output or codecs.
