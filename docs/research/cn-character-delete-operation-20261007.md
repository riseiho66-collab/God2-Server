## Source integration

`SharedLoginSources::World.deletion` supplies an explicitly bound common SQLite
repository and actual decision source. The existing composition forwards it to
`SharedWorldSelection`; defaults are empty and perform no deletion/success.
Selection retains the same admission registry installed on its world connection.
It resolves19 against exact retained native07 row/common-ID order, credential
aliases and current shared ownership. The temporary19 object is destroyed and
ingress credential bytes are wiped before any decision/storage provider runs.
No credentials go to the new scope, Lua, repository lookup or logs.

`SharedCharacterDeleteOperation` uses a server-created attempt pointer, verified
account/world-session/common-character and the independent native slot. The
selection designates that exact operation before calling its supplier. Create,
enter, concurrent/repeated delete and terminal close cannot borrow a busy owner.
The SQLite repository pointer must equal the actual Selection repository through
a normal base conversion; no downcast, separate CN database or profile synthesis.
An actual full stored snapshot is copied from that common account/ID. The
decision must carry the same snapshot, exact attempt scope, complete23-byte02
and a required observing authority callback. Unknown rules yield no decision.

For zero status, source code calls the prior concrete
`SharedCharacterRemoval::commit`, not a substitute erase callback. Its prepared
TW/CN offer invalidation and full-row SQLite CAS retain their existing semantics.
The authority callback runs at BeforeErase and BeforeCommit. BeforeErase also
rechecks native identity; BeforeCommit deliberately uses the designated operation
and current world ticket because the transaction already staged the root absent.
The required actual callback must observe real permission, online/world/guild
leases, pending operation/CAS and replay state, without writes, nested transactions
or executor yield. This round does not invent those native rules or receipts.

Complete native bytes/completion ownership are allocated before SQL. After
COMMIT and the prior immediate offer invalidation, queue gates require current
attempt/ticket, absent common ID and actual BeforeQueue authority. They do not
reuse invalidated native07 membership. Whole02 queue completion rechecks the same
state with AfterQueue authority. The successful owner stays alive and permits
only the existing actual terminal03 source/drain path following native0204.
Failure, disconnect or queue errors never restore a committed character or emit
a synthesized success/failure. Durable crash/replay recovery is still open.

A supplied nonzero02 must leave the exact stored row and native offer intact;
it requires BeforeQueue/AfterQueue authority and never invokes SQL removal. Only
after whole queue completion is that attempt released. Future requests resolve
new identity/authority; this does not assume a failure code's UI recovery meaning.
Missing/invalid source, CAS conflict, exceptions or stale ownership close the
local unsupported operation without guessed native replies. Queue booleans are
local transport outcomes, not client acceptance.
