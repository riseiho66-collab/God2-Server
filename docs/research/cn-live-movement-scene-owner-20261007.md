## Owned adoption

After the actual CN tail activates the common lease, adoption checks the exact
connection/account/offered character/session/generation, same presence object,
same `SharedInitialScene` lease, common native map catalog, original saved
position, scene revision and the exact `CnSceneAssets` instance used by the
initial factory. It reads direction from that retained full native2A's actual
`native_direction()` projection, not a movement packet/default.

Each initial scene can be claimed once. Mode2 owns its fully loaded native house
grid; mode0 owns the actual initialized outdoor window from the same initial
scene. No fresh synthetic cache, cloned initial baseline, empty/all-pass cells,
guessed viewport/camera or packet-coordinate /21 center is supplied. The asset
instance and common map/DB owner must outlive this controller. Paths remain
runtime resource provenance, not immutable content-hash or current native render
acceptance claims.

## Before common position CAS

`scene()` checks that the live actor position and the currently stored common
position/revision match, then returns its retained current native grid and actor
direction. `current()` compares exact lease, owner scene revision, map keys,
mode/direction, every grid byte/dimension/origin, and actual cache generation.
The new grid equality is a snapshot comparison, never permission.

The mandatory `Authority::authorize` supplies actual timing/pending/reset,
collision/path/corner/dynamic-entity, battle/transfer/resource constraints,
complete native5D and a real post-commit authority-publication callback. There is
no default authority, permission or request-index echo. Authorizer callbacks
cannot reenter this owner's mutation path. Full reply/resource preparation,
allocations and state rechecks occur before existing shared position CAS.

For mode0, the permit must also carry the actual native camera view AFTER the
step: camera pixels, viewport and loaded tile dimensions, map+34 and native owner
prefix. `prepare_camera` computes the recovered0046CE10/00473120 condition.
Only its actual switch condition enters `prepare_camera_switch`: retained-MBD
reuse, standalone replacement/reuse and already recovered known open-failure
null-slot branches use their actual resources. No switch is a qualified native
camera result, not a missing-data success. Mode2 rejects mode0 camera inputs.
Private instance/generation-bound camera/cache candidates remain pending until
the actual position commit. A new `current(PreparedCameraSwitch)` checks both
camera and cache identity/generation without mutation.

## After the actual commit

`publish()` requires the exact pending step, before position/scene revision,
common stored after position, unchanged map, requested coordinates and increased
DB revision. It consumes the pending permit once. Only then does it commit the
prepared cache/resource change and publish its conditional camera offset and
native visible-slot flags. It updates live position, actual step direction,
internal scene revision and cache generation before the real authority callback.
The existing SharedMovement pipeline subsequently submits registered TW/CN5E
and the fully supplied5D. No new packet is invented by this scene owner.

The next movement reads the new stored position and this live scene, rather than
reusing initial cells under the initial saved revision. The DB and cache/model
are ordered commits, not one ACID transaction. A post-CAS failure causes the
existing controller/transport cleanup and fresh owned reentry; durable position
is retained, never rewound after peers may have observed it. External mutation
of the retained cache invalidates the owner's expected generation.
