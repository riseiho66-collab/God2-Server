# CN normal initial scene assets to common prepared identity

This round adds an actual resource supplier, not a default callback: eighteen
CN asset sources are imported from the paused upstream through bounded raw
snapshots and original hashes. C++ include paths are adapted to `src/cn`.
CnSceneAssets also retains the actual CAN and selected plain/wrapped HMD paths
for indoor provenance; its parse/composition rules are retained.

No asset loader, Lua, client, server, build or test is executed in phase1. The
new source remains unhosted. Existing accounts/saves, TW behavior, native fonts,
IME/chat and Traditional/Simplified conversion are preserved.

## Actual supply chain

SharedInitialScene.prepare binds the exact connection's current verified common
account, committed world session, offered common character and inactive
SharedWorldPresence lease. It requires the real stored preparation position,
actor handle, full37-byte native2A and a nonzero revision supplied by the actual
scene owner. It never allocates a handle, derives one from a DB ID, selects a
spawn or generates unknown2A fields.

The actual common NativeMapCatalog row must match the pinned source/ordinal/raw
bytes and reserved position through SharedSceneIdentity. The CN resource row's
keys, declared category and raw MDT path must match the shared reference. This
is a catalog identity join; the declared category is not substituted for2A's
actor scene mode, and equal paths do not prove TW/CN geometry equivalence.

For normal initial mode2, the existing native family-base area0 row locates
CAN; CAN selects the area's actual HMD file. The native0516/plain resource reader
and HMDv1.6 mask/object composition supply the complete indoor grid. Actual CAN
and selected HMD paths are retained. For normal initial mode0, CAN selects MDT;
MDTv1.2 dimensions, MDLv1.6 placements, model ROM geometry and MBDv1.2 terrain
compose the real initial neighborhood. Model ROM and terrain ROM registries
remain distinct. Actual selected CAN/MDT/MDL/ROM/MBD paths are retained.

The preferred0516 wrapper rule and separate MBD timestamp rule are retained;
readers do not create the native disk cache. Outdoor placement preserves native
candidate/full3x3/clamp order and ordered object traversal. Its local projection
coordinates are camera/map outputs, never persisted actor destinations.
Missing resources, uninitialized backreferences, unsupported versions/modes or
unavailable neighborhoods return absence or throw; no empty grid is substituted.

After reading resources, ownership, current preparation and common map identity
are read again. The normal world selection source now requires this exact
snapshot and full2A before queuing02/2A. Ready must bind the same registry and
full lease, including generation. Selection retains the snapshot. CF transfer
explicitly cannot supply this normal initial snapshot; transfer geometry and
native reload/same-map lifecycle remain open rather than counted as complete.

## Movement handoff and boundaries

Once the lease is active, the actual WorldOwner can obtain a SharedMovement::Scene
at the exact initial stored position/revision using its actual actor direction
and unchanged scene-owner revision. The supplier rejects reuse after any stored
position or scene revision change. It preserves the initial outdoor center,
loaded-slot coordinates, grid and camera projection for the real owner's next
lifecycle step. Initial geometry does not implement live rotation, animation,
collision changes, permission, timing, pending-ring reset or5D issuance.

Resource paths record what was read; they are not immutable asset byte hashes.
The real owner must pin the loaded profile/revision across the scene lifetime.
Shared DB/catalog and native rules owners must outlive the controllers. Normal
initial data are not restoration, transfer, portal, battle or later61 evidence.
Modes1/3, legacy resource versions, non-ASCII/native path variants and the pinned
catalog's leading-backslash row remain explicitly unsupported pending evidence.
No path normalization workaround, TW asset fallback or custom navigation rule
is introduced.
