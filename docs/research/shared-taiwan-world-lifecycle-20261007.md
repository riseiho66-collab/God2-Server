## Source ownership and ordering

Each actual new dual-world TW connection needs its own
`SharedTaiwanWorldLifecycle::hooks(presence, visibility, entered)` installed in
its Session character handlers. Creation and callbacks use the serial game
executor and the identical shared presence/visibility objects as CN.
The scene's actual `entered` callback is mandatory, publishes the real world
actor, sets the actual InWorld state, and supplies real native resources/view
records. No default acceptance callback is provided.

1. Existing selection and full2A builder execute unchanged. Session records the
   actual selected character ID and invokes the optional prepared hook before
   queuing the unchanged02/2A. The hook checks the full decoded geometry against
   the common repository's saved position and exact revision, then reserves the
   shared lease with common character/handle exclusion. No DB write occurs.
2. Existing TW tail parser is keyed by the selected character ID. This extension
   therefore requires that untruncated ID to equal the actual2A low14 handle;
   larger/independently mapped IDs remain open, never silently truncated.
3. Transport validates the full native tail, invokes the existing frozen
   `world_ready` callback, and then sets its synchronized ready flag. Only then
   does it post the optional common ready callback to the game executor.
   Later world ingress stays paused until that callback completes. Scene output
   may use the actual send API now; API submission is not client acceptance.
4. The common hook rechecks the actual socket/account/character/initial saved
   position, activates the same generation lease, and calls the actual scene
   owner. Its final state must be InWorld, still owned, ready and unchanged in
   initial saved position; failure rejects the connection rather than inventing
   a replacement placement or reply.
5. Session retains a one-shot game-executor cleanup. It retires visibility
   incarnations/removes observers with their retained73, then releases the exact
   presence generation. Both owners get cleanup even if output throws; existing
   disconnect work is independently invoked afterwards. No adapter destructor
   or on_disconnect replacement is needed. Failed pre-tail/activation/transport
   paths use the same retained cleanup.

When the extension is absent, the existing entry/tail/reading path has no new
game handoff or additional policy. Existing login, chat/IME, conversion, fonts,
character serializers, callbacks and client binaries remain unchanged.
