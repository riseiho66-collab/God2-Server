# BF 面板雙列表送包來源，2026-10-06

同版 verified native image SHA-256 `149c1b4510a2dee85eb988d3f6c05785a69cbf50bb8fb751af7d9814a5a6e763` 的有界原始 bytes、反組譯與 slice 雜湊見 `artifacts/integration/packet-connections-20261006/bf-ui-row-producer-v3.json`。這輪僅做靜態來源還原；沒有建置、測試、執行客戶端、驗收或部署。

面板事件先要求選取索引 `UI+97FA0 != -1`，並依 `UI+97FA2` 模式、目前數量 `UI+96958` 與對應上限 `UI+9697A` 或 `UI+96B9E` 篩選。C2S BF logical 9 bytes 的八位元組 body 由選取列組成：byte2 取 `UI+9695E`；byte3 將偶數模式 `0/2/4/6` 或奇數模式 `1/3/5/7` 映為 `1/2/3/4`。這是兩個不同的 UI 列族，不能把全部 BF 當成每日購買。

| UI 模式 | 選取列 | body bytes0..1 | body bytes4..7 | 立即送出 |
|---|---|---|---|---|
| 奇數 1/3/5/7 | `UI+96BA4 + signed(UI+97FA0)×48` | 列首 u16 | 列+2 的 u16 零擴充為 u32，重複列搜尋可能替換 | `CFC87` |
| 偶數 0/2/4/6 | `UI+96980 + signed(UI+97FA0)×6` | 列首 u16 | 列+2 的 u16 零擴充為 u32，重複列搜尋可能替換 | `CFE77` |

兩個族系都會搜尋其他列段。若在後段找到相同列首 key，控制流改走 `CFCB0` 或 `CFEA0`，將八位元組 body 存在 UI child `+3AE48`，打開確認框；確認時的直接送包點是原先已知的 `842E4`。因此三處**直接** queue caller 其實涵蓋「兩個立即路徑＋共用確認路徑」，另有每日面板 dialog32 跳共用 queue `8450B` 的第四條來源分支。`842E4` 並非獨立於兩個列族的第三種持有資料來源。每日 dialog32 的 body 仍是另一個 `item:u16 | 01 | 01 | displayed_amount:u32` 形狀。

目前只知道本地欄位來源和送包分支。列首 key、列+2 數量的服務端權威來源及操作語義，和 S2C BE/BF 面板區域列表的因果關係尚未證明；也沒有價格、貨幣、原子交易、失敗重試或因果回覆。正式來源仍只收納預設關閉的 FD 綁定每日購買意圖，其他 BF 變體沒有權威 handler。此輪新增完整雙向遊戲路徑為 0。
