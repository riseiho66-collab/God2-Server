## Concrete missing path

TW257 C90 publishes AB detail from actual owned query/visible-issued target,
private written/current entry sources and the complete relevant party. C91
consumes its private detail permission while issuing an existing pending Join
and S54 preview. It does not itself make the requester a party member.
The existing C58 answer subsequently changes authoritative membership.

Before TW260, C91 reset Query.detail and left only raw last_join_request.
The watcher checked participants and members only while detail existed.
Consequently membership could change after consent while directory rows stayed
identical, and no A7 was generated to clear the previous native AB view.
This was a real missing source lifecycle, not another unknown opcode.

C91 permission. Presentation records describe the actual source selected for an
AB submission, not client Written/ACK or rendered acceptance. Retained material
cannot authorize C91. Failed new C90 selection revokes old private permission

evidence the native client cleared its old AB. Successful replacement AB,
complete A7 or real query retirement replaces/retires that presentation source.

## Exact private entry qualification

Independent static review identified a stale-entry case in the first candidate:
after a participant reenters, its current listing may carry new private entry
material with identical serialized bytes. Byte comparison alone cannot establish
that the old presentation receipt remains current. The refinement checks the
actual captured private receipt of owner, target and every member using its
written status and recorded-game-owner current_on_game predicate. It marks old
presentation invalid without rejecting an otherwise valid new listing.

The same case could affect the existing C91 permission source. Old private
Detail owner/target/all-member receipts are now checked before any staged
NativeParty observe/action, and again after all observers before publication.
This fixes the exact source gate and adds no consent permission or rule.

The watcher publisher also repeats pure old-receipt guards for presentations
that the prepared plan keeps, after every source observer. An invalidated
presentation removed by its prepared A7 is deliberately excluded from that
guard, so its stale receipt cannot itself prevent the clearing A7.
The planner performs read-only recorded-owner receipt checks as well as COW
data preparation; it is not described as a data-only function.

## Remaining limits

One issued-WORD tombstone, capacity or framing conflict can still fail the whole
watcher plan and defer this invalidation/fanout. Reconciliation also requires a
successful original handler run; a later original failure after an earlier
unrelated commit can defer refresh until another actual event. No identity is
silently rebound.
Publication and ordinary recipient submission are not atomic socket delivery;
later IO failure can leave a prefix and does not roll back the source commit.
Successful native A7 local clearing does not prove socket Written, native ACK or
rendered acceptance. No new native executable, schema/table, activation or
deployment was introduced. General post-battle private entry renewal, current
DA appearance, the full64/native consent adapter and original server refresh
policy remain open. Native evidence reuses4 exact spans599 bytes/226 sites;
