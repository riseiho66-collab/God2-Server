# TW 共用移動正式入口來源與 CN 接收槽位（第170輪）

本輪三組子代理完成台服共用移動核心、實際移動來源與陸服接收槽位追查；主代理完成 Application 接入。共修改八個 C++ 來源檔（六個既有、兩個新增）。這是來源串接增量，尚未配置真正的原生場景權威物件，也尚未由普通 Main 選用或部署，不能算新增完整可玩路徑。

## 實際來源增量

`SharedWorldPresence::ready_lease` 以實際 Session、帳號、角色及有效世代取得已發布的共用場景身分。它不把移動後位置再與入場時的原始位置比較；每一步仍重新讀取目前保存位置及 revision。

`SharedTaiwanMovement` 增加強持有規則與真正 WorldOwner 的明確入口。新的 owned 分支在原生場景、授權及發布回呼前後重新確認身分，完整 5D 與所有觀察者 5E 投影在唯一位置 CAS 前準備。已提交前綴不因後續失敗倒退；投遞不宣稱為跨連線原子交易或客戶端已收到。

新增 `SharedTaiwanMovementSource` 保留真正規則、WorldOwner 工廠及實際容量；整批格式先檢查，再取得實際已完成入場發布的 lease。每個槽位持有精確 lease 與弱 Session，控制器與實際權威物件由遊戲執行緒持有及釋放。外部回呼經 QualifiedWorld 委派，原生數值、權限、格子及 5D 全部仍須由真正來源供應。

`SharedWorldHostPlan` 新增明確 opt-in 工廠，從同一個 Application Context 與共用世界組裝真正的 movement、release、invalidate_active 三個回呼。Application 的遊戲執行緒 vault 持有真正來源；Session 只取得弱 facade。它要求非同步場景與完整原生入場來源、已完成發布的實際 Session，以及獨立移動 dispatcher。混合 world-record dispatcher 仍需另外整合，不能被此入口默默取代。

被捕捉的巢狀呼叫須由最外層 vault 一路使當前來源失效，QualifiedWorld 才會在下一次 CAS 前拒絕。斷線時先釋放此來源精確保存的控制器，再清理共同場景；即使傳輸身分已清除也能釋放舊物件。來源本身不移除共用 registry，不關閉或釋放後繼世代。

既有 borrowed 控制器與候選移動回呼保留。原始聊天、IME、帳號、存檔、認證、頭像、字體與繁簡轉換未變更。沒有新增原生數值、默認成功授權、假 5D 或 CUSTOM 至 CN 的提升。
