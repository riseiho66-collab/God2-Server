# Live Offline Monster Construction

## Result

Two fresh original-hash client processes complete the entire original115C90
participant constructor, including its real ROM loader, attachments, text,
metadata, status and RET4. Side1 and side0 both return EAX1 with the original
stack depth. This closes the earlier actual/Unicorn boundary at11602A.

It does **not** recover original monster attack/defense or four base attributes.
The precise experiment is an offline world plus an explicitly supplied logical
identity selector. It is not a zero-input native monster spawn, actual received
packet, complete battle initialization, visible gameplay or server acceptance.
No numeric capability record is supplied, and no values enter the database.

## Input And Ownership

Existing guarded runner uses only its disposable original-hash working copy,
program firewall, transport stop-before-call breakpoints, real local scene,
source-backed pagefile compatibility and reversible timer/entry bindings.
No desktop automation, credentials, listener, official endpoint or retired
archive is used. Original executable disk bytes remain unchanged.

slot0, variant0400. Its level, instance identity, flags and other opaque bytes
are zero test inputs, **not** recovered monster values. Only position differs
between sides0 and1. Both live EnyName lookups yield the same26-byte source:

`160fa454b84fc06e000000000000000000000000000000000000`

and `data2/fight/eny1/eny1015.rom` on side0. Each raw source record and entire

The actual world already creates the battle object at world+A7E05EC, its
renderer/ROM bank and all168 actor pointers. We do not create substitute
ownership structures or provide successful game-function return values.

## Reproduce

Use a new run ID; existing evidence directories cannot be overwritten:

```powershell
python -B -m tools.strike_lab.current_offline_client_run --run-id offline-monster-NEW --timeout 90 --enter-local-world --probe-native-monster 1
python -B -m tools.strike_lab.current_offline_monster_review artifacts/runs/offline-monster-NEW
python -B -m unittest tests.research.test_current_offline_monster_live -v
```

The constructor-only mode is deliberately separate from the event-loop mode.
Owned CDB/client processes close after bounded observation, including failures.
The next capability requirement is still an original identity-bound producer
for physical/magical attack and defense. A working model or UI number alone
does not meet that requirement, and this result does not promote production
combat from its current movement-only implementation.
