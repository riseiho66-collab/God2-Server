## Actual source defect and implementation boundary

Previously B4 had no world parser/handler. A B4 emitted by that producer would
reach `Session.cpp`'s world contract rejection and disconnect the client;
this is a source-path finding, not an observed runtime reproduction.
`RecoveredBattleRowPreference` now parses the complete bounded0/1 grammar.
Ingress is enabled only on the actual exclusive whole-bag normal-entry
branch with owned_normal_movement_response_custody and no common lifecycle
or factory. The three world callbacks existing alone are insufficient.
Session construction enforces the same flag/source requirement. Common-lease
and other legacy branches remain B4 unsupported; they are not claimed fixed.
The actual final wrapper prevalidates the whole batch before any original
callback or storage mutation. Only B4 request values and run boundaries are
copied. The old handler receives exact original Session-owned record spans,
including no-B4 C28/terminal/empty input, preserving occurrence receipts.
Multiple B4 choices mixed
in order with actual Movement and Tick are supported; both movement and
callback reply output offsets remain attached to each contiguous original run.
Economic, battle and other mixed mutations still require a joint owner and
are rejected before any prefix mutation. They are not claimed fixed.

CUSTOM-0142 saves only authenticated explicit B4 user choice bytes as E8 in
the existing independent `tw_b4_row_choice_e8_v1` record kind. The fixed
analysis pin identifies this source policy; it is not a remote executable
attestation. No peer string selects another pin. The original2A kind, raw
role/profile bytes and schema constraints remain unchanged.

Each changed choice owns its complete common root and saved position and
uses exact account/character/client/kind/full-tuple CAS. The actual private
normal initialization must be current and entry_written. Its actual callback
response is captured before reads; output frame, merged bytes and next cache
are allocated before persistence. Read/SQL callbacks that reenter, retire,
change account/character/phase/battle/INIT/response or stop the host poison
the operation. The optional repository PureCurrent checks only retained
in-memory currentness after the final SQL/readset and immediately before
COMMIT, with reentered checked again. A postcommit retirement suppresses old
E8 but preserves the durable save; no stale retry or fictional rollback.

Ready marks pending without inventing a private INIT. On the next actual
world callback after entry_written, a new/current normal entry reloads the
explicit saved choice and registers its E8 component with the original
capture/expect response owner. Historical saved root/position are provenance,
never this Session's present location or permission. No saved choice means
no E8/default. Missing schema/read failure is distinct from absence: ordinary
world input retains its original response, records source unavailable once
for that INIT and waits for a new INIT or a real B4 attempt. Actual B4 save
failure is rejected, never swallowed as an empty successful operation.

The explicit `character_native_world_entries` extension must already exist
at runtime. This pass did not inspect/install any game database and cannot
claim that prerequisite is met. Runtime schema/error behavior, real FIFO
acceptance, reconnect and movement mixed acceptance remain untested.

This fixes a concrete ingress defect and implements custom durable UI choice
replay. It does **not** establish native server persistence, full battle
front/back deployment, primary/pet initial slots, battle-exit reset semantics
or the remaining SOS invite/join/settlement owner. Those remain OPEN.
