## Input source and ownership

The existing whole-frame classification permits one context notification and
Ticks, rejects mixed/repeated operations before mutation, and qualifies the own
actual final fullwrite, private Finished room/readset/memberlocks, owner/pose and
retained departure. An early viewer can reach this point while the peer's final
output or resource save remains pending. This round does not change that rule.

Only a binding with its genuine WorldDeparture starts the barrier. Historical
bindings retain their context-only behavior and gain no return authority. The
actual synchronous world-records callback must prepare it using the original
accepted Written PK entry hold and the exact Session final-delivery pointer.
Raw IDs, a durable submitted flag, a copied payload or a standalone post cannot
mint it. Session qualifies transport lineage; Publication qualifies Finished
gameplay and the native context payload.

The new private token retains the original Session, game executor, common-world
identity, battle delivery identity, entry hold and normal initialization. It
does not clone a normal Entry or set a fabricated Written bit. Each Publication
binding retains a per-viewer game-owned adapter with a weak parent lifetime and
binding. Network handlers keep private data and a weak adapter only.

## Actual asynchronous cut

Preparation publishes a pending token. The network strand waits for the current
world callback ACK to validate acceptance and enqueue its response before
considering quiescence. It rejects retained world bytes, pending records or a
skill prefix; it never erases those bytes and treats them as new world input.
An outstanding read must complete its cancellation with operation_aborted and
zero bytes. Ambiguous nonzero/error completion fails closed. The existing
cancellation slot applies to that read, not to unrelated writes.

The barrier also waits for the actual write queue and byte count to drain. Its
stage is reached from the ordinary ACK/input continuation, cancelled read and
write completion after removal of the completed item. A single posted job, an
idle atomic snapshot or a timer is not a drain receipt. Read/resume/feed and
queued game admission observe the separate pending token.

The exact callback retains its minted token independently of the network
pending slot: timeout/close may retire that slot before the callback returns.
Only its accepted ACK, after response enqueue, stamps acknowledgement. A
callback exception or ACK post failure takes the failure path, never a success
stamp. Cleanup of that returned callback cannot require its pending slot still
to be installed. The game executor must remain alive and drain; destruction or
failure of every scheduling attempt cannot guarantee callbacks or cleanup.
Specifically, if retirement already cancelled the timer before this callback
returns and both ACK post and cleanup retry fail to allocate, no remaining
callback necessarily clears game_busy or notifies the peer owner. The token's
currentness still fails; universal timeout cleanup is not claimed for that cut.

After the strand establishes Ready it posts to the actual serial game executor.
Publication checks the exact token/binding/context revision/payload/final-write
pointer and retained departure, requalifies the existing durable terminal guard,
and rechecks currentness. Session separately stamps owner acceptance. A Ready
callback is not an accepted callback and neither is permission to resume WORLD.

Ready is maintained only while the explicit barrier owns the transport. New
output while Ready invalidates it rather than preserving a stale empty-queue
claim. Queue insertion paths, including held common publications, must obey
this condition; a central write-start check alone would miss held enqueue.
The separate deadline remains in force after Ready/acceptance. Timeout, source
expiry, shutdown, callback rejection or handoff failure closes the Session;
the Publication failure adapter closes its paired binding. There is no clean
abort back to old battle input after the native terminal return arm has run.

Cancellation of a zero-byte read does not prove the TCP receive buffer contains
no older bytes. This is a bounded local transport cut, not a remote epoch or
native-consumption proof. Later full return still needs an exact final strand
consume/commit boundary and a policy for native coalesced input.
