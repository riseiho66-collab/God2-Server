therefore not accepted as stable startup merely because two returns were seen.

## Memory Protection

Native protection snapshots retain AllocationProtect PAGE_EXECUTE_WRITECOPY and
current client PAGE_READWRITE. A separate read-only helper opened the same PID
with PROCESS_QUERY_INFORMATION and called GetProcessDEPPolicy at packed entry,
candidate entry and window end. All three calls succeeded: flags=0,
permanent=false. Exact timestamps/results are in dep-policy.json.

Microsoft documents flags=0 as DEP disabled for that process. This is direct
process-policy evidence consistent with executing the observed client bytes;
it does not prove PE executable section flags, explain why that policy was chosen,
or record every protection transition. No DEP/firewall/system security setting
was changed. False permanent means the observed setting was not reported fixed
for the process lifetime; do not extrapolate it beyond the sampled stops.

Reference: [GetProcessDEPPolicy](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getprocessdeppolicy).
